## Evidence Limits

- The LLM judge was disabled, so `judgeScore` values are not evidence of judged output quality. Ledger events record `judgeEnabled=false` with explicit launcher evidence.
- Input and output token counts come from PAST-Bench traces. This historical run predates request-level instrumentation, so cache, reasoning, request, and retry evidence remains unavailable in its ledger rather than being retroactively inferred.
- Request count is reconstructed from assistant messages and is labeled as such. It must not be interpreted as provider API-call evidence.
- Provider retries and monetary prices were not captured. The report therefore states neither retry totals nor USD cost.
- This run validates integration, persistence contrast, and lifecycle evidence collection only. It does not establish statistical effectiveness.

## Privacy Check

The generated ledger stores run-scoped opaque record IDs, character counts, operation metadata, and relative evidence paths rather than memory text or content-derived fingerprints. A scan of the ledger and checked-in launcher/configuration files found no GPT-Luna key, common credential pattern, user-specific `/home` or `/mnt` path, or memory content from the smoke.

## Usage Follow-up

RSIMem now extends the generic PAST-Bench runtime and trace contracts with sanitized request-level model usage. A separate live probe after this run verified four GPT-Luna requests whose token buckets summed exactly to the episode aggregate. Historical traces remain readable and retain `null` for evidence they never captured.
